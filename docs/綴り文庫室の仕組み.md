# 綴り文庫室の仕組み

# 綴り文庫室とは

**綴り文庫室**は、ローカルLLM（Ollama）を利用して、その場で物語を生成するテキストアドベンチャーゲームです。

プレイヤーの選択によって物語は変化し、背景画像・BGM・音声も場面に合わせて切り替わります。

プレイするたびに異なる展開が楽しめることが、本作の特徴です。

---

# ゲーム全体の流れ

```text
ジャンル選択
        │
        ▼
ローカルLLMへ物語生成を依頼
        │
        ▼
LLMがJSON形式で結果を返す
        │
        ├── 本文
        ├── 選択肢
        ├── 正解選択肢
        ├── background_tag
        └── bgm_tag
        │
        ▼
ゲーム側が演出を開始
        │
        ├── 背景画像表示
        ├── BGM再生
        ├── VOICEVOX読み上げ
        └── 選択肢表示
        │
        ▼
プレイヤーが選択
        │
        ├── 正解 → 次のシーン生成
        └── 不正解 → BAD END
```

---

# ストーリー生成

物語は、あらかじめ用意されたシナリオではありません。

ゲームはローカルLLMへ、

* 選択したジャンル
* 現在までの物語
* 前シーンまでの要約

などを渡し、続きを生成してもらいます。

LLMは本文だけでなく、

* 選択肢
* 正解ルート
* 背景タグ
* BGMタグ

なども同時に返します。

そのため、プレイするたびに異なる物語が生まれます。

---

# 背景画像の仕組み

AIは画像そのものを選んでいるわけではありません。

例えば、

```text
background_tag = forest
```

というタグを返した場合、

ゲーム側は

```text
assets/backgrounds/forest.png
```

に対応する画像を表示します。

つまりAIが行っているのは、

**「この場面なら森が合いそう」という判断**です。

実際に表示する画像は、作者があらかじめ用意した素材になります。

## 背景画像について

背景画像は、ChatGPTと相談しながら制作し、それぞれに適切なタグを設定しています。

---

# BGMの仕組み

BGMも背景画像と同じ考え方です。

例えば、

```text
bgm_tag = mystery
```

と返された場合、

ゲームは

```text
assets/bgm/mystery.mp3
```

を再生します。

## 音楽について

AIが音楽ファイルを聴いたり、解析したりしているわけではありません。

作者があらかじめ

* mystery
* fantasy
* peaceful

などのタグを決め、

その雰囲気に合う音源を選び、対応するファイル名で登録しています。

AIは物語に合うタグを返し、ゲーム側が対応するBGMを再生しています。

---

# VOICEVOXによる読み上げ

LLMが生成した本文はVOICEVOXへ送られ、

自動で音声へ変換されます。

そのため、プレイヤーは物語を読むだけでなく、音声でも楽しむことができます。

---

# 選択肢と分岐

各シーンには複数の選択肢があります。

LLMは、

* 正解となる選択肢
* 不正解となる選択肢

も生成しています。

ゲームはその結果を判定し、

正解なら次のシーン、

不正解ならBAD ENDへ進みます。

---

# 物語の記憶

長い文章をそのままLLMへ送り続けると効率が悪くなるため、

各シーンは短い要約を生成してもらって保存。

次のシーンを生成する際には、

その要約を利用して物語の流れを維持しています。

---

この解説は OpenAIの対話型AI「ChatGPT」を使用して製作しています。
