# 綴り文庫室の仕組み

「綴り文庫室」は、このPC上のOllamaモデルに物語を生成してもらう、全5場面のテキストアドベンチャーです。プレイヤーの選択に応じて物語が進み、背景画像・BGM・任意のVOICEVOX読み上げを組み合わせて表示します。

この文書はv4のソースをもとにした概要です。準備・設定・開発手順は [README.md](../README.md)、実行ファイル版の操作は [README_PLAY.md](../README_PLAY.md)を参照してください。以下のファイルパスは `src/` を基準にしています。

## ゲーム全体の流れ

| 段階 | ゲーム側とAIの役割 |
| --- | --- |
| 開始 | プレイヤーがジャンル・モデルを選択。「自由に綴る」では希望文を開始設定へ整理する |
| 場面の生成 | AIへ本文・2つの選択肢・選択結果・背景タグ・BGMタグ等を依頼する |
| データの確認 | 返答をJSONとして読み、必須項目や正解位置などをPython側で検証する |
| 表示 | 背景・音楽を切り替え、本文を表示し、読み上げがONなら音声を準備・再生する |
| 選択 | 不正解ならBAD END。正解なら結果文と次の場面、最終場面ならGOOD ENDへ進む |
| クリア後 | 後日談・クリアメッセージ・AIの短評・プレイ記録・終了案内を順に読む |

本文や結果はボタン操作で読み進めます。AIの返答がそのままゲーム全体のルールを決める構成ではありません。

## ストーリー生成

ジャンル名・生成方針、場面番号、その場面の役割、前の場面までの短い要約などをOllamaへ送ります。「自由に綴る」では入力原文と整理した設定も生成方針へ含めます。

OllamaのチャットAPIにはJSON形式での返答を依頼します。本文は少しずつ受信して表示するのではなく、完成した返答を受け取ってから、画面で1文字ずつ表示する演出を行います。

JSONの形式不正や必須項目の不足などでは、初期設定で最大3回まで場面生成を試します。AIの文章が自然であることや、物語の一貫性を完全に保証するものではありません。

## 選択肢と正解位置

正解位置は、ゲーム開始時にPython側で5場面分を決めます。AとBが3回・2回、または2回・3回になるよう並べ、AIには指定した位置が正解になる内容を生成するよう依頼します。AIが別の正解位置を返した場合は検証で拒否します。

不正解では、その場面の生成時に用意したBAD ENDを表示します。「直前の選択肢へ」で戻ると、同じ場面・同じ選択肢で再挑戦でき、場面の再生成はしません。

通常場面で正解すると、要約を更新して次場面を生成した後、正解結果を表示します。「次のシナリオへ」を押すまで次場面の本文は表示されません。最終場面の正解では、追加エンディングを生成してからGOOD END以降を読み進めます。

## 物語の記憶とv4の効率化

過去の本文をすべて次の要求へ蓄積せず、短い要約を引き継ぎます。初期設定の要約上限は100文字です。

v4では、通常場面と「正解した後の要約」を同じ返答で生成します。その要約は正解が確定したときだけ採用し、BAD ENDや再挑戦では物語の記憶へ反映しません。空・不正な型・長すぎる要約の場合は、従来の別生成へ戻します。別生成も失敗すると、確定した結果からローカルの簡易要約を作り、進行を続けます。

これはLLMの呼び出し回数を減らすための仕組みです。すべての環境で一定割合の高速化を保証するものではありません。

## 背景画像

AIは画像そのものを見たり選んだりするのではなく、65種類の場所タグから場面に合うものを返します。画像を出さない `none` も使えます。

例えば `background_tag` が `forest` なら、ゲームが `assets/backgrounds/forest.png` 等の候補を探します。同じタグへ複数画像を登録でき、直前の画像をできるだけ避けながら候補を選びます。対応画像がない場合も進行は続けます。

背景は事前に用意した素材で、プレイ中に新しい画像を生成する機能ではありません。既存の作者説明では、背景画像はChatGPTと相談しながら制作・タグ付けしています。具体的な生成ツールや各画像の制作履歴までは、ソースから確認できません。

配置規則は [画像について.md](画像について.md)を参照してください。

## BGMと効果音

AIが通常場面で指定するBGMタグは次の7種類です。

| タグ | 雰囲気 |
| --- | --- |
| `calm` | 静か・穏やか |
| `bright` | 明るい・楽しい |
| `mystery` | 謎・調査・違和感 |
| `tension` | 緊迫・追跡・危機 |
| `battle` | 戦闘・対決 |
| `sad` | 悲しみ・別れ |
| `horror` | 怪異・恐怖 |

ゲームが同名のMP3を `assets/bgm/` から探し、なければOGGを候補にします。タイトル・エピローグ・GAME CLEARでは、アプリが `title`・`ending`・`game_clear` を指定します。正解・BAD END・GOOD ENDには別の効果音を使います。

AIが音源を聴いて解析しているわけではなく、タグの説明から雰囲気を選び、事前配置した音源をゲームが再生します。BGM10曲・効果音3種類の生成元と利用上の注意は [README.md](../README.md#収録音源について)を参照してください。

## VOICEVOXの読み上げと先読み

読み上げがONなら、生成した文章を短く分割してVOICEVOXへ送り、生成したWAVをpygameで順番に再生します。先頭の音声が準備できてから本文表示と再生を始め、後続の音声は並行して準備します。

v4の先読みは、現在の文章を読み上げる間に、次の音声区間の先頭1チャンクを準備するものです。通常場面では正解結果の後の場面、エンディングでは次の読み上げ区間が対象です。先読みした本文や音声を、先に表示・再生することはありません。

停止・再プレイ・キャンセル時は古い処理を無効化します。ただし、外部エンジンへ送信済みの処理はしばらく続く場合があります。VOICEVOXの合成速度そのものを変更する機能ではありません。

## 記録と確認

バックログは表示済みの文章を保持し、クリア後にテキスト保存できます。音声保存は生成済みWAVを書き出す機能で、未再生の先読み音声等を含む場合があります。途中から再開するセーブ機能はありません。

動作ログ、時間の計測、診断用スクリプト、自動テストは保守・原因調査用です。詳しくは [testsの説明](tests_guide.md)と [toolsの説明](tools_guide.md)を参照してください。
